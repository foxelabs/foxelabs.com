## What it does

WordPress has no setting for how long an unattended session should stay open,
or how long a login should last at all. **Auto Logout** adds both.

Set an idle timeout in minutes and any session that stops being used is ended —
the user lands on the login screen with "You were signed out because your
session was inactive." Only the idle device is signed out; their other devices
keep their own sessions and their own countdowns.

Idle logout ships switched off. Turning it on seeds a 15-minute timeout you can
raise or lower, up to 30 days.

## Warn before signing out

A countdown dialog appears before the session ends — 60 seconds by default — so
someone who stepped away mid-form can choose to stay signed in, sign out
immediately, or do nothing and be signed out when it hits zero. Set the warning
to zero to sign people out with no dialog at all.

Activity in one tab keeps every other tab alive with no extra server requests,
and a tab that was suspended re-checks the clock when it comes back rather than
acting on a stale timer.

## Per-role timeouts

Five minutes for administrators and shop managers, an hour for subscribers who
are only reading — the usual shape for a compliance-driven site. Roles you don't
list fall back to the global timeout, and custom roles registered by another
plugin or your theme appear automatically.

When a user holds several roles that each have a rule, the **shortest** timeout
wins. That's deliberately the reverse of
[Limit Per Role](/software/plugins/loggedin/limit-per-role), where the most
permissive cap wins: a session limit denies access, so the loose value is the
safe one, while an idle timeout only ends a session nobody is using.

## Session length

Idle timeout and session length are different controls, and most compliance
rules ask for both. WordPress logins are valid for 2 days, or 14 days when
**Remember Me** was ticked. Auto Logout replaces either or both with your own
durations, applied through the `auth_cookie_expiration` filter — so a login
can't stay valid for a fortnight just because someone keeps clicking.

## Enforcement without cron or polling

Enforcement is server-side. Closing the tab, disabling JavaScript, or killing
the script buys nobody a longer session: the check runs early on every
authenticated request. There's no cron job and no polling loop — page views
renew a per-device "last active" timestamp, throttled to at most one write per
quarter of the timeout and never more than one a minute.

Background requests deliberately don't count as activity. The WordPress
heartbeat fires from any open admin tab every 15 to 60 seconds, so treating it
as activity would keep an unattended dashboard signed in forever. Long stretches
of genuine single-page work — the block editor, a WooCommerce screen — are
covered by a lightweight ping the browser sends only while you're actually
interacting.

Pair it with [Real-time Logout](/software/plugins/loggedin/realtime-logout) so
an idle logout propagates to every open tab within the polling interval, and
with [Active Sessions](/software/plugins/loggedin/active-sessions) to see and
clear sessions by hand.
